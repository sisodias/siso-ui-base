SISO UI Base — Architecture

A domain-tuned forge → rank → vote loop for AI-generated UI. The thing no one in the prior art has actually built.

Sub-repo: oracle-streaming/siso-ui-base/ · Manifest: registry/repos.json (25 repos) · Clone everything: ./clone.sh · Generated 2026-06-01

Thesis

The prior-art sweep found two families that nobody has connected: tools that encode design taste as a gate (impeccable & ~8 peers) and vision models that auto-score a UI screenshot like a designer would (deepeval, Q-Align, UIClip & ~6 peers). Every existing tool picks one half and stays generic — "good design" treated as universal. SISO UI Base wires both halves into one pipeline and tunes it to a single domain: the cam-model performer cockpit. A forge agent generates variations, a stacked gate ranks them 0–100 against our brand brief (warmth / playful / clarity — not generic prettiness), an adversarial Critic red-teams the survivors, and only the top few reach Shaan's Needs-You inbox for a taste vote. The output is reusable across all 40 models via a brand-agnostic engine + per-brand skin.

The 5-stage pipeline

Each stage is cheap-first: kill obvious failures before spending on expensive judges. A variation only advances if it clears the prior gate.

1

Deterministic gate DO NOW

Run impeccable detect + our exact-threshold rules + Lighthouse accessibility. Catches AI slop (gradient text, glassmorphism, Inter overuse, pure black, cramped padding) and broken contrast/ARIA. Free, fast, no LLM. A cockpit that fails contrast fails the warmth test by definition.
Steals: impeccable (27 rules) · pencilplaybook (exact thresholds: disabled=40%, hover ≥8% lightness delta, dark text #E2E8F0 not #FFF) · aislop (0–100 scored gate w/ per-engine breakdown) · lighthouse (a11y 0–100 hard gate)
2

Fast aesthetic pre-score DO NOW

A CLIP/SigLIP scorer drops visual disasters in <10ms/image before any expensive VLM runs. Use the stylized-calibrated model since our look is glossy-candy, not photographic.
Steals: aesthetic-predictor-v2-5 (SigLIP, stylized-calibrated, fast) · NIMA (rating distribution — high variance = polarizing design, filter out the risky ones)
3

Domain rubric judge DO NOW — weekend-viable

A vision LLM scores each survivor on our axes — warmth, playfulness, clarity — using a rubric built straight from the brand bible. Plain-English criteria, editable, interpretable, zero training data. This is the fastest path to a working ranker.
Steals: deepeval (Multimodal G-Eval; wrap our existing Playwright harness) · promptfoo (llm-rubric → ranked matrix across all variants in one CLI call) · design-critique-mcp (screenshot-in / 0–100-JSON-out as an MCP) · ui-ux-review-agent (app_context field → domain-specific feedback)
4

Adversarial Critic NEXT

A red-team agent whose mandate is to find structural failure, not style nits: "why would this fail the performer mid-grind at hour 6?" Two reviewers run in parallel — one rules-based, one aesthetic — and both must pass. Disagreements go to an explicit tiebreaker.
Steals: design-cognition-skill (the Critic role) · designpowers (two-reviewer parallelism: WCAG/COGA + Nielsen) · design-skill-os (Red Team audit module) · our own adversary skill
5

Human vote — Needs-You inbox HAVE IT

Only the top-N survivors reach Shaan, each shown with all four upstream signals (slop-pass, pre-score, rubric breakdown, critic verdict). He votes on taste alone — never on obvious failures. The inbox is the UI Base's existing Needs-You tab.
Steals: agent-inbox (interrupt-as-inbox-item: typed payload = screenshot + diff + meta) · lastest (MCP approve/reject primitives so Claude+Codex vote through the same interface) · taste-skill (VARIANCE/MOTION/DENSITY dials Shaan tunes, not binary)

Why ours beats the field — the 4 frontier gaps

1. No one wires taste-gate → visual-judge. Family A stays soft LLM guidance; Family B stays research demos. A screenshot-in → ranked-verdict-out loop that runs unattended and gates a vote does not exist at production quality anywhere. That is literally our pipeline.
2. No multi-agent taste council. Every repo targets a single agent. Nobody runs generate → adversarial Critic → tiebreak between rules-signal and judge-signal. We already have the orchestrate harness for exactly this.
3. Taste treated as universal. Fintech-dashboard rules ≠ performer-cockpit rules. Encoding ORACLE's exact aesthetic (child-not-veteran, glossy-candy-on-white, the AI-slop ban-list) as a machine-readable domain gate is the whole edge.
4. Soft vibes, not CI assertions. Only aislop + pencilplaybook make failures measurable. The winning move: exact thresholds as deterministic checks (hover ≥8% lightness delta), not prose.

Build order

  1. NOW Stage 1 deterministic gate: install impeccable (already a skill here), encode our threshold rules from design-system.json, wire Lighthouse a11y. Doc the gate in the forge lane.
  2. NOW Stage 3 rubric judge: wrap the existing Playwright screenshot harness with deepeval G-Eval; rubric = brand bible. This is the weekend MVP — a working ranker with no training data.
  3. NOW Registry contract: reshape library[]/components[] toward shadcn registry-item JSON; serve /api/r/<name>.json from the hub.
  4. NEXT Stage 2 pre-score + Stage 4 Critic + Engine/Skin + dials.
  5. RESEARCH Stage 3-pro: fine-tune Q-Align on ~50 hand-rated cockpit screenshots → a ranker calibrated to Shaan's taste specifically. Use UIClip's jitter trick to manufacture negative anchors cheaply.
