What it is

A drop-in, agent-neutral package that turns any coding-agent fleet (Claude or Codex) into an elite human-in-the-loop UI builder. Agents build UI as self-contained HTML; a human reviews variations in a clean React viewer + voice/chat; agents iterate; winners graduate to production React components. The batteries that make this good — a taste-grading pipeline, component libraries, domain frameworks — ship inside the package. The human stays on taste; the agent does production. This is the HTML-first loop, proven clean in practice: generate → show → react → iterate → graduate.

Why it exists (the problem)

Taste doesn't scale and AI defaults to slop. The quality bar lives in one head; every panel needs that eye or it drifts; at 40 models × N platforms × M panels you can't eyeball everything. SISO UI Base encodes the bar once and enforces it at machine scale — so a human reviews pre-vetted, scored options and never wastes a glance on obvious failures.

The home (settled)

Own git repo at ~/SISO_Workspace/siso-ui-base/ — a peer of SISO_Agency/ and SISO_Knowledge/, not buried in either.

Why here, and not the alternatives:

  • Not oracle-streaming/ — it's agent infrastructure for every project; Oracle is just tenant zero. Trapping it in one tenant is the original mistake.
  • Not ~/.claude/ — it's agent-neutral. Codex builds UI too. A Claude-only home is wrong.
  • Not (yet) SISO_Agent_Base/ — that's the correct eventual owner (it already fans skills out to .claude + .codex via symlink/install.sh), but it is mid-reramp (2026-06-01). Building on shifting ground = merge churn. So: build standalone now, migrate onto its skill-shelf when the reramp settles.

The package is shaped Superpowers-style (SKILL.md + framework/ + app/ + commands/) precisely so the later migration is one mv + a symlink — zero rework.

The three-layer delivery model (proven by Superpowers + Claude)

LAYER 1 — SOURCE (canonical, agent-neutral)
  ~/SISO_Workspace/siso-ui-base/        ← this repo. the product + the package.

LAYER 2 — FAN-OUT (when migrated to Agent_Base; mirrors design-directions/impeccable)
  ~/.claude/skills/ui-base  ┐ symlink → the source
  ~/.codex/.../ui-base      ┘            (one source, both harnesses)

LAYER 3 — PER-PROJECT TENANT DATA (lives in each consuming project)
  oracle-streaming/.uihub/   ← Oracle's DNA, board, variations, blessed components
  <any project>/.uihub/      ← its own tenant data

Engine is global + agent-neutral. Taste DNA is per-project. Same split as Superpowers (global package + project data) and Claude (~/.claude + .claude/).

The loop (the spine)

you: "build me 4 variations of the goal bar"
  → agents write 4 standalone .html into the tenant's variations dir
  → each auto-scored 0-10 BEFORE you look (slop never reaches you)
  → React viewer shows them ranked, TOP badge on the winner
  → you react in voice: "2nd one but warmer, kill the pill"
  → agent iterates → viewer shows v1→v2 side-by-side with score deltas
  → you: "bless it"
  → blessed HTML = source of truth; agent ports to React pixel-for-pixel, screenshot-diffs to verify

Core vs Batteries (the future-proofing)

CORE — never rewrittenBATTERIES — hot-swap, 10x later
The loop (forge→render→score→react→iterate→graduate)Judge — Codex-vision today → cheap fast vision → your fine-tune

The loop calls interfaces (Judge, LibraryProvider, FrameworkProvider, Gate, AgentBridge), never names a model. Future drops swap implementations behind a fixed seam.

The moat

Every graduation emits a labeled (html, score, blessed) triple. A competitor clones the loop in a week — they cannot clone 3 months of your chat-rail approvals. After 50 graduations the rubric is a regression suite; after 500, a fine-tune dataset. The calibration anchor (Oracle chat rail = 9.24) makes taste verifiable + portable: it proves the machine still agrees with the human, and catches model drift. The loop is the engine; the proprietary per-domain taste corpus is the fuel.
